01 / Install

Installation

Requires PHP >= 8.0 plus the standard openssl (TLS) and zlib (gzip) extensions. CI runs the full unit/protocol suite on PHP 8.0 through PHPUnit 9.6 and on PHP 8.1–8.5 through PHPUnit 10.

Composer
composer require erikwang2013/messaging-php
  • No rdkafka, ext-zmq or ext-redis installation is needed, and neither is any official broker SDK.
  • The only runtime dependencies are Guzzle and the PSR-3 logging interface, both installed automatically by Composer.
  • Framework adapters ship in the same package and are used on demand; without a framework, use plain PHP directly.

02 / Auto-registration

Framework auto-registration

No extra commands are needed after installation. Each framework discovers the package through its own Composer mechanism and registers it on install or boot:

FrameworkAutomatic behaviour
Laravelextra.laravel discovers the provider and facade; mergeConfigFrom merges the default config at runtime
ThinkPHPextra.think discovers the service; the standard app's post-autoload-dump runs service:discover and vendor:publish
webmanThe install hook copies the plugin config to config/plugin/erikwang2013/messaging-php/ (existing files are kept)
Hyperfextra.hyperf.config discovers the ConfigProvider; the shipped defaults are used until config is published
Yii2The yii2-extension extra.bootstrap registers the messaging component when the application boots
Yii3extra.config-plugin is merged by yiisoft/config at runtime

No manual copying or registration. To customise, use the publish or override path documented for that framework; no action is needed to use the defaults.

03 / Quick start

Quick start

Redis Streams: publish, consume, ack

Redis Streams
<?php

use Erikwang2013\Messaging\Contract\Message;
use Erikwang2013\Messaging\Contract\ReceiveOptions;
use Erikwang2013\Messaging\Manager;

$mq = new Manager([
    'default' => 'redis',
    'connections' => [
        'redis' => [
            'driver' => 'redis',
            'host' => '127.0.0.1',
            'port' => 6379,
            'group' => 'orders',
            'consumer' => 'worker-1',
        ],
    ],
]);

$connection = $mq->connection();

$result = $connection->publish('orders', Message::json(['id' => 1], ['trace' => 'abc']));
echo $result->id; // Redis Stream ID

while ($message = $connection->receive('orders', new ReceiveOptions(timeoutMs: 5000))) {
    try {
        // handle the message
        $message->ack(); // XACK
    } catch (Throwable $e) {
        // no ACK: the message stays in the PEL and is recovered by XAUTOCLAIM / XCLAIM
        error_log($e->getMessage());
    }
}

The destination (the first argument to publish / receive) is the Redis Stream key. The first receive creates the consumer group automatically and starts from 0, so any backlog is consumed as well.

consume() loop sugar

consume() is only loop sugar; you still call ack() after successful processing:

Consume
use Erikwang2013\Messaging\Contract\ConsumeOptions;

$connection->consume('orders', function ($message): void {
    // handle the message
    $message->ack();
}, new ConsumeOptions(timeoutMs: 5000, maxMessages: 100));

NATS Core: subscribe first, then publish

Core NATS delivers messages only to subscriptions that exist at publish time. Ordering matters especially when producer and consumer use separate connections: the consumer calls receive() once to establish the subscription, then the producer publishes. Otherwise messages are lost immediately (at-most-once, no persistence).

NATS Core
// assumes a nats connection is configured in connections
$nats = $mq->connection('nats');

$nats->receive('orders.created', new ReceiveOptions(timeoutMs: 1)); // establish the subscription first
$nats->publish('orders.created', new Message('hello'));

$message = $nats->receive('orders.created', new ReceiveOptions(timeoutMs: 1000));

NATS Core ack() / reject() both throw UnsupportedFeatureException; use JetStream for persistence and acknowledgement semantics (not implemented yet).

06 / Development

Development and testing

Commands
composer install
composer test       # tests/Unit + tests/Protocol, no external services
composer phpstan    # PHPStan level 5
composer cs         # PHP-CS-Fixer check

The unit/protocol suite currently has 739 tests and 2661 assertions; framework unit tests are skipped automatically when the corresponding framework is not installed. On PHP 8.0, use vendor/bin/phpunit -c phpunit-9.xml to run the same suite (PHPUnit 9.6); PHP 8.1–8.5 use PHPUnit 10. CI also runs full PHP 8.0 linting plus a runtime smoke test.
