P1 / Driver

ActiveMQ Classic

driver: activemq · STOMP 1.2 over TCP · Erikwang2013\Messaging\Driver\Stomp. Shares StompDriver with Artemis; the ActiveMqPreset supplies the port, requeue and delay headers.

Key limitations

  • Requeue is implemented as re-send + ACK, so duplicates are possible.
  • No consumer groups; delay is carried in STOMP headers.
  • The receive buffer defaults to buffer_limit = 10000 per destination.
Full guide (Chinese)

P1 / Driver

ActiveMQ Artemis

driver: artemis · STOMP 1.2 over TCP · Erikwang2013\Messaging\Driver\Stomp. The ArtemisPreset handles NACK semantics, delay headers and queue-creation timing.

Key limitations

  • STOMP NACK is a discard; there is no requeue capability.
  • Consumers must subscribe before messages are published.
  • The receive buffer defaults to buffer_limit = 10000; no consumer groups.
Full guide (Chinese)

P1 / Driver

Beanstalkd

driver: beanstalkd · Beanstalkd text protocol · Erikwang2013\Messaging\Driver\Beanstalkd. The destination is the tube name; the driver speaks the text protocol directly without a broker SDK.

Key limitations

  • No headers, key or batch publishing.
  • Unacknowledged messages are redelivered after their TTR expires.
  • No automatic reconnect or connection pool; a BURIED put raises RequestException.
Full guide (Chinese)

P1 / Driver

NATS Core

driver: nats · NATS Core text protocol · Erikwang2013\Messaging\Driver\Nats. JetStream is not implemented; this driver covers core publish/subscribe only.

Key limitations

  • At-most-once: messages are lost while a subscriber is offline.
  • Subscribe before publishing; publish() does not create a subscription.
  • ack() and reject() throw UnsupportedFeatureException; queue_group provides group semantics.
  • Per-destination buffer defaults to buffer_limit = 10000; idle connections reconnect on the next publish.
Full guide (Chinese)

P1 / Driver

NSQ

driver: nsq · NSQ v2 TCP protocol · Erikwang2013\Messaging\Driver\Nsq. Pure PHP implementation of the NSQ TCP protocol.

Key limitations

  • The channel must exist first; the driver creates it lazily on the first receive(), so messages published earlier are lost.
  • Published messages carry no id; PublishResult::id is always null.
  • No delay, TLS, AUTH or compression; long gaps between reads can hit the broker heartbeat timeout.
Full guide (Chinese)

P1 / Driver

Redis Streams

driver: redis · RESP2 · Erikwang2013\Messaging\Driver\Redis. Consumer groups and acknowledgements use XGROUP, XREADGROUP and XACK.

Key limitations

  • reject(true) is unsupported: unacked messages stay in the PEL; recover them with XAUTOCLAIM or XPENDING + XCLAIM.
  • No delay messages and no TLS configuration (plaintext TCP in v1).
  • One message per receive() (COUNT 1); max_length uses approximate MAXLEN ~ n trimming.
Full guide (Chinese)

P2 / Driver

Azure Service Bus

driver: azure-service-bus · data-plane REST · Erikwang2013\Messaging\Driver\Azure. Uses Shared Access Signature (SAS) authentication over HTTP with Guzzle.

Key limitations

  • REST + SAS only: no AMQP, Microsoft Entra ID (OAuth), transactions, sessions or duplicate-detection management.
  • Peek-lock: finish before the lock expires, or renew it yourself; expired complete/abandon returns 404.
  • reject(false) completes the message; it is not a dead-letter operation.
  • Entities must exist in advance; 429/5xx are not retried automatically; delay resolution is one second.
Full guide (Chinese)

P2 / Driver

GCP Pub/Sub

driver: gcp-pubsub · Pub/Sub v1 REST JSON · Erikwang2013\Messaging\Driver\Gcp. Authenticates with a service-account JWT (RS256); no Google Cloud SDK required.

Key limitations

  • REST pull only, one message per receive(); no streaming pull.
  • The ack deadline defaults to 60 seconds; long tasks must finish or be split before the lease expires.
  • At-least-once delivery; no exactly-once semantics; dead-letter policy is managed in GCP.
  • Topics and subscriptions are not created automatically; attempts() is always 1.
Full guide (Chinese)

P2 / Driver

AWS Kinesis

driver: kinesis · Kinesis Data Streams JSON API + SigV4 · Erikwang2013\Messaging\Driver\Aws. Shard consumption is expressed as a checkpoint cursor.

Key limitations

  • Checkpoints are in memory only; a process restart resumes from TRIM_HORIZON unless your callback persists progress.
  • No queue-style reject(), dead-letter queue or consumer coordination; every instance reads the whole stream.
  • No headers or delay; KPL aggregation, enhanced fan-out and cross-account consumption are unsupported.
Full guide (Chinese)

P2 / Driver

AWS SNS

driver: sns · SNS Query API + SigV4 · Erikwang2013\Messaging\Driver\Aws. Publishes to a topic; delivery and consumption are handled by SNS and downstream services.

Key limitations

  • Publish only: receive() and publishBatch() throw UnsupportedFeatureException.
  • No FIFO topics, MessageStructure=json or direct SMS sending.
  • Topic management, subscribe/unsubscribe and attribute updates are outside the driver.
Full guide (Chinese)

P2 / Driver

AWS SQS

driver: sqs · SQS JSON protocol + SigV4 · Erikwang2013\Messaging\Driver\Aws. Supports acknowledgements, requeue, delay and long polling.

Key limitations

  • Message bodies must be valid UTF-8; binary payloads are rejected before sending.
  • FIFO queues do not support per-message delay; the driver sets MessageGroupId but not MessageDeduplicationId.
  • Queue management, dead-letter policies and the 256 KiB limit are delegated to AWS and surfaced as RequestException.
Full guide (Chinese)

P3 / Driver

RabbitMQ

driver: rabbitmq · AMQP 0-9-1 over TCP/TLS · Erikwang2013\Messaging\Driver\RabbitMq. The destination is the queue name; messages use the default exchange.

Key limitations

  • Default exchange only; no custom exchanges, bindings, topic/fanout routing or basic.get.
  • No publisher confirms; basic.publish returns once written to the socket.
  • One connection and one channel; no reconnect or pool; prefetch bounds unacked messages.
  • Queues are not auto-deleted; no delay support.
Full guide (Chinese)

P3 / Driver

ZeroMQ

driver: zeromq · ZMTP 3.1 + NULL mechanism · Erikwang2013\Messaging\Driver\ZeroMq. Supports PUB/SUB and PUSH/PULL without ext-zmq.

Key limitations

  • At-most-once and brokerless: no persistence, ack, requeue, delay or consumer groups.
  • Slow joiner: subscriptions must reach the publisher first; publishing before subscribing loses messages.
  • Each destination buffers at most buffer_limit messages (default 10000).
  • No bind/listen, TLS, CURVE/PLAIN, reconnect or socket monitor; headers/key/delay/batch are unsupported.
Full guide (Chinese)

P4 / Driver

Kafka family

driver: kafka (aliases: redpanda, automq, confluent, eventhubs) · Kafka wire protocol · Erikwang2013\Messaging\Driver\Kafka. One implementation covers Kafka and compatible products.

Key limitations

  • No SASL, transactions, idempotent producer or exactly-once semantics.
  • PLAINTEXT/TLS only; publishing compression is unsupported, and consumption supports gzip only.
  • Classic consumer groups with the range assignor only; no cooperative-sticky, static membership or KIP-848.
  • Tombstones become empty strings; admin APIs, time-based offset lookup and auto_offset_reset=none are unsupported.
Full guide (Chinese)

P5 / Driver

Pulsar

driver: pulsar · Pulsar binary protocol v11 · Erikwang2013\Messaging\Driver\Pulsar. Experimental: covers the minimal produce/consume subset.

Key limitations

  • No authentication (TLS transport is available), batching, compression, schema, transactions or chunking.
  • No partition-topic routing; use a specific partition such as ...-partition-0.
  • Shared subscriptions; delayed delivery resolves at about one second.
  • Subscriptions start at Earliest; publishing is not retried automatically.
Full guide (Chinese)

P5 / Driver

RocketMQ

driver: rocketmq · RocketMQ 4.x remoting · Erikwang2013\Messaging\Driver\RocketMq. Experimental: publish, pull consumption, ack/requeue, delay levels and routing.

Key limitations

  • No transactions, message traces, ACL/authentication or Alibaba Cloud ONS/SASL.
  • No SQL92 or TAG filtering; no compression; no batch publish.
  • No broker long polling: idle consumers poll every 20–50 ms.
  • Master brokers only; no slave reads or automatic broker failover; 18 default delay levels.
Full guide (Chinese)
